Philosophy
기본기를 중요하게 생각합니다
라이브러리를 블랙박스로 두지 않습니다. HTTP 요청이 소켓에서 어떻게 조립되는지 확인하기 위해 Socket부터 WebClient까지 직접 구현해봤고, Redis를 쓸 때는 자료구조별 특성을 실험으로 확인한 뒤 선택했습니다.
트레이드오프를 항상 따져봅니다
정답인 기술은 없다고 생각합니다. Redis 장애 시 기능을 열지 막을지, 토큰을 클라이언트와 서버 중 누가 가질지, MSA와 모놀리스 — 무엇을 얻고 무엇을 포기하는지를 비교한 뒤 선택하고, 그 이유를 설명할 수 있게 기록합니다.
테스트로 배포의 불안을 줄입니다
빈약한 테스트로 배포가 불안했던 경험 이후 테스트를 우선순위에 뒀습니다. 유니트에서는 아키텍처 경계까지 테스트로 검증하고, API 문서를 테스트가 통과해야만 생성되는 구조로 만들었습니다.
